# Suction Actuator — SBD-14U 스텝모터 드라이버

## 개요
- 모델: SBD-14U (모터뱅크)
- 2상 바이폴러 스텝모터 드라이버, RS-485(Modbus RTU)로 제어
- 42각 스텝모터 후면 일체형 장착
- 제품사이즈: 42(L) x 42(W) x 13(H) mm

## 전원
- VCC(VDD) 입력전압: DC 7V ~ 24V (24V 권장)
- 출력전류: 0.5A/phase (정상), 최대 2A/phase
- 드라이버 자체: 0.5A, 12W(max)
- **24V / 150W 파워서플라이 사용 가능** (150W@24V ≈ 6.25A, 충분한 여유)
- 극성 주의: VM(+)/GND 반대연결 시 드라이버 손상 가능

## 단자구성
보드에 3개의 터미널 블록이 있음:

| 위치 | 핀 | 의미 |
|---|---|---|
| 상측 | B, A, G, VM | RS-485_B, RS-485_A, GND, 모터(드라이버) 구동전원 VCC(12-24V) |
| 좌측 | A+, A-, B+, B- | 모터 상(phase) 결선 (2상 바이폴러) |
| 하측 | L, R, G, V | 좌측 리미트, 우측 리미트, GND, 리미트 센서용 전원 VCC(12-24V) |

- 리미트 입력: **NPN 광전스위치(포토센서) 또는 마이크로스위치만 가능** (PNP 비호환)
- 리미트 미사용 시 하측 G/V는 연결 불필요. 사용 시 하측 V/G에도 전원 필요 (상측 VM과 같은 라인에서 분기 가능)

## RS-485 통신 설정
- 프로토콜: Modbus RTU
- 통신속도 기본값: **9600 bps**
- 패리티: 없음
- 정지비트: 1
- 슬레이브(장치) 주소 기본값: **0x01**
- 사용 Function code: `0x03`(레지스터 읽기), `0x06`(단일 레지스터 쓰기), `0x10`(다중 레지스터 쓰기)
- 결선: USB-RS485 어댑터 A ↔ 드라이버 A, 어댑터 B ↔ 드라이버 B (T+/T- 라벨인 경우 T+→A, T-→B로 시작, 응답 없으면 반대로 교체)

### 이 환경에서 사용하는 포트
```
/dev/cu.usbserial-A04AC9IK
```
(Mac에서는 `tty.*`보다 `cu.*`를 사용 — carrier-detect 대기 없이 바로 통신 가능)

## 데이터 프레임 구조

**FC 0x03 (레지스터 읽기)**
- 송신: 장치주소(1B) + 0x03 + 레지스터주소(2B) + 레지스터개수(2B) + CRC(2B)
- 응답: 장치주소(1B) + 0x03 + 데이터길이(1B) + 데이터(Nx2B) + CRC(2B)

**FC 0x06 (단일 레지스터 쓰기)**
- 송신/응답: 장치주소(1B) + 0x06 + 레지스터주소(2B) + 데이터(2B) + CRC(2B)

**FC 0x10 (다중 레지스터 쓰기)**
- 송신: 장치주소(1B) + 0x10 + 레지스터주소(2B) + 레지스터개수(2B) + 바이트수(1B) + 데이터(Nx2B) + CRC(2B)
- 응답: 장치주소(1B) + 0x10 + 레지스터주소(2B) + 레지스터개수(2B) + CRC(2B)

CRC16: 표준 Modbus RTU (poly 0xA001, init 0xFFFF), 프레임 끝에 **low byte, high byte** 순서로 부착.

## 레지스터 맵

| 주소 | R/W | FC | 비트폭 | 기능 |
|---|---|---|---|---|
| 0x0020 | R/W | 03/06 | 16bit | 모듈 주소 (범위 0x0000-0x007F) |
| 0x0021 | R/W | 03/0x10 | 32bit | 통신속도 (2400/4800/9600/14400/19200/38400/56000/57600/115200) |
| 0x0023 | R/W | 03/06 | 16bit | 운전전류(High 8bit)/구속전류(Low 8bit), 각 0-31. `I=(값+1)/32*Imax`, SBD-14U Imax=2A |
| 0x0024 | R/W | 03/0x10 | 32bit | 원점복귀속도 (pulse/s), 원점복귀시에만 사용, 전원차단 후 자동 저장 |
| 0x0026 | R/W | 03/0x10 | 32bit | 초기속도 (pulse/s), 전원인가 직후 속도 |
| 0x0028 | R/W | 03/0x10 | 32bit | 운전속도 (pulse/s), 전원차단 시 삭제됨 |
| 0x002A | W | 06 | 16bit | 정역회전 모드 운전 (비트맵, 아래 참조) |
| 0x002B | R/W | 03/0x10 | 32bit | 좌표모드 운전 - 목표 스텝값 (비트맵, 아래 참조) |
| 0x002D | W | 06 | 16bit | 운전정지 (0x0000=잠금, 0x0001=잠금해제/자유회전). 정지 후 2초간 다른 지령 금지 |
| 0x002E | R | 03 | 16bit | 상태 읽기 (비트맵, 아래 참조) |
| 0x002F | R/W | 06 | 16bit | 브레이크/솔레노이드 밸브 제어 (구매시 옵션, 출력전류 500mA 이내) |
| 0x0030 | R/W | 06 | 16bit | 분주비 (4/8/16/32/64/125/256) |
| 0x0031 | R/W | 03/0x10 | 32bit | 클로즈루프 데이터 읽기/쓰기 |

### 0x002A 정역회전 모드 (비트, AH 앞 AL 뒤)
| 비트 | 기능 | 1 | 0 |
|---|---|---|---|
| 13 | 센서미사용 원점복귀 | 스톨검출로 원점설정 | 단순 정역회전만 |
| 12 | 센서사용 원점복귀 | 좌우리미트로 원점설정 | 단순 정역회전만 |
| 4 | 모터방향 | 정방향 | 역방향 |
| 3 | 우측 광커플러 유효성 | 정회전 중 LOW일 때 정지 | 정회전 중 HIGH일 때 정지 |
| 2 | 좌측 광커플러 유효성 | 역회전 중 LOW일 때 정지 | 역회전 중 HIGH일 때 정지 |
| 1 | 우측 광커플러 활성화 | 활성화 (정회전시만 유효) | 비활성화 |
| 0 | 좌측 광커플러 활성화 | 활성화 (역회전시만 유효) | 비활성화 |

주의: 센서 사용 원점복귀 시 대응 광커플러 반드시 활성화. 노센서 원점복귀 시 모든 광커플러 비활성화. 안 지키면 오류 0xffff.

### 0x002B 좌표모드 (비트, AH 앞 AL 뒤)
| 비트 | 기능 |
|---|---|
| 31 | 좌표 방향 (1: 원점의 -방향, 0: 원점의 +방향) |
| 27 | 우측 광커플러 유효성 (0x002A 비트3과 동일 규칙) |
| 26 | 좌측 광커플러 유효성 |
| 25 | 우측 광커플러 활성화 |
| 24 | 좌측 광커플러 활성화 |
| 23-0 | 목표 스텝값 (최대 0x00FFFFFF) |

### 0x002E 상태 (비트, AH 앞 AL 뒤)
| 비트 | 기능 |
|---|---|
| 15 | 1: 모터 정지, 0: 모터 운전 (마지막 펄스 후 1ms 뒤 갱신) |
| 14 | 1: 과열 경고 (120℃ 도달) |
| 13 | 1: 과열 극한 (136℃ 도달, IC 냉각까지 자동 사용금지) |
| 8-4 | 모터 실제전류 (0-0x1F), 정지상태에서는 구속전류값 |
| 1 | 우측 스위치 상태 |
| 0 | 좌측 스위치 상태 |

## 실제 결선/구동 트러블슈팅 기록

### 통신 불능 → 해결 과정
완전 무응답 상태에서 아래 순서로 원인을 좁혀감:
1. 전원(VM-GND) 미공급이 1차 원인이었음 — 멀티미터로 보드 단자 직접 측정해서 확인
2. USB-RS485 변환기가 **RS-422 모드**로 설정되어 있었음 → RS-485(2-wire) 모드로 전환
3. T+/T- ↔ A/B **극성**이 반대였음 → 교체 후 정상 응답 확인
4. GND 공통 연결은 이번 케이스에서는 불필요했음 (판매처 확인)

**확정된 통신 환경:**
- 포트: `/dev/cu.usbserial-A04AC9IK` (이 Mac 기준, FTDI FT232R 어댑터)
- 결선: T- → A, T+ → B
- 보레이트 9600 / 장치주소 0x01 (출하 기본값 그대로 사용 중)
- 쓰기(FC06/0x10) 명령이 가끔 1회성으로 무응답 나는 경우 있음 — 재시도(retry) 로직으로 대응 중 (버스 노이즈로 추정)

### 탈조(진동만 하고 전진 안 함) → 해결 과정
1. **초기속도(0x0026) 출하 기본값이 51200 pulse/s**로 설정되어 있었음 — 분주비 256 기준 풀스텝 환산 시 시작부터 200step/s(60rpm급)로 가속 없이 즉시 점프하는 셈이라 바로 탈조. **1500 pulse/s로 낮춰서 해결.**
2. **운전전류 부족** — 초기엔 보수적으로 run=10(≈0.69A)로 설정했으나, 실제 모터(LSM-NK174218, 1.5A/phase 정격) 대비 전류가 한참 모자람. **run=23, hold=8 (run≈1.5A, hold≈0.56A)로 올려서 해결.**
3. **파워서플라이 공유 문제** — 크러셔 모터(정격 약 24V/6.8A ≈ 163W)와 액추에이터를 150W 파워서플라이 하나에 같이 물려서 전류가 부족했음. **액추에이터 전용으로 전원 분리 후 정상 구동 확인.** 150W는 크러셔 모터 단독 정격조차 못 채우므로, 공용으로 쓰려면 최소 200W 이상 파워서플라이로 교체 필요.

### 현재 확정된 운전 파라미터
| 항목 | 값 |
|---|---|
| 운전전류 / 구속전류 (0x0023) | run=23, hold=8 (≈1.5A / ≈0.56A) |
| 초기속도 (0x0026) | 1500 pulse/s |
| 운전속도 (0x0028) | 3000~24000 pulse/s 범위에서 테스트, 분주비 256 기준 체감 속도 느림 (아래 참고) |
| 분주비 (0x0030) | 256 (출하 기본값, 미변경) |

**체감 속도가 느린 이유**: 분주비 256이면 1회전에 51,200pulse 필요. 8000 pulse/s ≈ 0.156회전/초 → 리드스크류 리드(4~10mm)에 따라 실제 리니어 속도는 약 0.6~1.6mm/s 수준으로 매우 느리게 느껴짐. 체감 속도를 올리려면:
  - pulse/s를 수만~수십만 단위로 더 올리거나
  - 분주비를 낮춤(256→32/16 등, 위치분해능은 거칠어짐)

### 호밍(원점복귀) 방식 — 결정: 센서없는 방식(스톨검출) 채택
포토센서 없이 **0x002A 레지스터 bit13 (센서미사용 원점복귀, 스톨검출로 기계적 끝단 찾아 원점설정)** 방식으로 진행하기로 결정. 센서사용 방식(bit12, 좌우 리미트센서 필요)은 보류.
- 장점: 별도 센서 결선 불필요
- 주의: 스톨검출 기반이라 기계적 끝단에 반복적으로 부딪히며 원점을 찾음 — 구조物(리니어스테이지, 커플러)에 무리가 가지 않는지 확인 필요. 반복 내구성 측면에서 센서방식보다 불리할 수 있음.
- 아직 `sbd14u_driver.py`에 전용 `home()` 메서드는 없음 — `jog(forward=..., home_no_sensor=True)`로 호출 가능하나 테스트 전. 원점복귀속도(0x0024)도 아직 미설정 (출하 기본값 그대로).
